# OpenAI Responses-API Migration (chat) + Voice Currency Bump Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (or subagent-driven-development) to implement this plan task-by-task.

**Goal:** Move the OpenAI CHAT provider from `/v1/chat/completions` to `/v1/responses` so gpt-5.6-family models get **function tools + reasoning together** and every OpenAI reasoning model lights up the thinking channel; bump the (already-GA) realtime voice stack to `gpt-realtime-2.1`; retire the legacy `whisper-1` telephony stragglers. The frontend SSE contract does not change by one byte.

**Architecture:** Two new transports in `chat_routes.py` — `stream_openai_responses` + `call_openai_responses` — replace the chat-completions pair behind the SAME dispatch sites and SSE/return contracts. A new ToolVault injector format (`openai_responses`, flat tool defs with `strict: false`) feeds them. Stateless per turn: `store: false`, full input each turn, tool loop replays the previous round's output items verbatim plus `function_call_output` items, with `include: ["reasoning.encrypted_content"]` so reasoning survives multi-round tool loops. Voice needs a catalog/default bump only (protocol already GA since 2026-05-19).

**Tech Stack:** FastAPI + httpx SSE (raw dicts, NOT the SDK's typed client — live fields like `message.phase` are missing from SDK types), ToolVault injector, pytest, live probes against api.openai.com (real key on box).

## Evidence base (all live-probed 2026-07-09, artifacts in scratchpad `probe_out/`; plan cites what's proven, not assumed)

- Driver verbatim: chat/completions + gpt-5.6-sol + function tools → 400 `param=reasoning_effort` ("use /v1/responses or set reasoning_effort to 'none'").
- `/v1/responses` accepts ALL probed models (gpt-5.1, gpt-5.6-sol, gpt-4o, gpt-4o-mini, o3) → **full cutover, no dual path**.
- Tool defs are FLAT `{type:"function", name, description, parameters, strict}`. **Omitting `strict` defaults to `strict:true` and the API SILENTLY REWRITES the schema** (probe 8: `required:["city"]` mutated to `["city","units"]`, `additionalProperties:false` injected). ToolVault schemas have optional params → **send `strict: false` per tool**. (This OVERRIDES the older Phase-3 checklist's "add strict:true" line — that predates the live probe.)
- Stateless tool loop (`store:false`) proven on gpt-5.1 AND gpt-5.6-sol: round-2 input = original messages + ALL round-1 output items replayed VERBATIM + `{type:"function_call_output", call_id, output:"<string>"}`. With reasoning: `include:["reasoning.encrypted_content"]` and replay the reasoning item verbatim (encrypted_content ~1.1KB); replaying a reasoning item WITHOUT encrypted_content under store:false → hard 404. Dropping it entirely also works on 5.6-sol, but replay-verbatim is the spec-safe recipe.
- Streaming event map (full observed sequence saved): `response.reasoning_summary_text.delta`→thinking; `response.output_text.delta`→content (BOTH `phase:"commentary"` preamble messages and `phase:"final_answer"`); `response.output_item.added(item.type==function_call)` carries name+call_id IMMEDIATELY→tool_start; `response.function_call_arguments.done`+`output_item.done`→execute→tool_result; `response.completed` carries the FULL final Response (usage + output items for next-round replay — no `include_usage` dance); errors = `response.failed` (carries `response.error`), bare `error` event, `response.incomplete` (`incomplete_details.reason`).
- Usage renames: `input_tokens`/`output_tokens`/`output_tokens_details.reasoning_tokens`/`input_tokens_details.cached_tokens` (+ live-only `cache_write_tokens`). **Android hard-parses `prompt_tokens`/`completion_tokens` from the usage SSE event** (ChatViewModel.kt:2068-2075) → the transport MUST translate back before emitting.
- gpt-5.6 live behaviors absent from SDK types: `message.phase` (commentary/final_answer), reasoning echo `context`/`mode` fields, effort default **medium** (gpt-5.1 defaults **none**; 5.1 rejects `xhigh`). At low effort/trivial prompts NO reasoning item is emitted — thinking channel must tolerate absence.
- Vision: `{type:"input_image", image_url:"data:...", detail}` inside user content; input text parts are `input_text` (output side is `output_text`).
- Delta events carry an `obfuscation` pad — send `stream_options: {include_obfuscation: false}`.
- Voice: realtime stack ALREADY GA-protocol (2026-05-19 migration; session.type="realtime", output_ event names, no Beta header). Live `/v1/models` newest: `gpt-realtime-2.1`, `gpt-realtime-2.1-mini` — both ACCEPT WS connects (session.created echoes model) but are BLOCKED by our allowlist today. Repo discipline (SNAP-20260520-6731): listing ≠ acceptance — full production session.update must be WS-verified before a default flip (gpt-realtime-2025-08-28 is listed yet WS-rejected close 4000).
- Stragglers found: `whisper-1` (telephony recording STT: twilio_routes.py:1481-1502, phone/bridge.py:2929-2953, pinned by test_stt_config.py:9); web-search tool model `gpt-4.1` (web_tools.py — already ON /v1/responses, just an old model); TTS stays as-is (quality-first memory: no silent tier changes; `gpt-4o-mini-tts` is a mini tier).
- In-repo Responses prior art: `web_tools.py:185-231` (_responses_search, raw requests) and the CU driver `openai_cu/` (richest: item handling). The CU/frontier loops use `previous_response_id` — chat must NOT cargo-cult that (stateless-per-turn doctrine: full input, `store:false`).
- Org-level note for Brandon (not a code change): this org's responses echo `service_tier:"priority"` without requesting it — project default with possible cost implications; also `billing:{payer:"developer"}`.
